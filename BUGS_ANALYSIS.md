## 🐛 КРИТИЧНІ БАГИ

### 1. **Відсутність Foreign Key у моделі Reminder**
**Файл:** `models/reminder.py`
**Проблема:** Таблиця `reminders` не має Foreign Key на `users.telegram_id`, що може призвести до orphan records
**Ризик:** HIGH - можуть накопичуватися нагадування для видалених користувачів
**Рішення:** Додати ForeignKey з cascade delete

```python
user_id: Mapped[int] = mapped_column(BigInteger, ForeignKey("users.telegram_id", ondelete="CASCADE"), nullable=False, index=True)
```

### 2. **Проблема з parse_mode у markdown**
**Файл:** `handlers/program_handlers.py` (рядок 86, 202, 216)
**Проблема:** Використання `**bold**` без вказівки `parse_mode="Markdown"`
**Ризик:** MEDIUM - текст не форматується, показує зірочки
**Рішення:** Додати `parse_mode="Markdown"` до всіх message.answer/edit_text

### 3. **Race condition у ReminderService**
**Файл:** `services/reminder_service.py` (рядок 40-48)
**Проблема:** Немає перевірки чи нагадування вже було відправлено сьогодні
**Ризик:** MEDIUM - може відправити кілька нагадувань за одну хвилину
**Рішення:** Додати поле `last_sent_date` та перевіряти його

### 4. **Некоректна обробка винятків**
**Файл:** `services/database_service.py` (рядок 60-62)
**Проблема:** Exception перехоплюється, rollback виконується, але exception пробрасується далі без логування
**Ризик:** MEDIUM - складно дебажити
**Рішення:** Додати logging.error перед raise

```python
except Exception as e:
    logger.error(f"Error updating user profile: {e}")
    await session.rollback()
    raise
```

## ⚠️ СЕРЕДНІ БАГИ

### 5. **Відсутність індексів**
**Файл:** Всі моделі
**Проблема:** Немає індексів на часто використовуваних полях (workout_date, created_at)
**Ризик:** MEDIUM - повільні запити при великій кількості даних
**Рішення:** Додати `index=True` на workout_date, created_at в критичних таблицях

### 6. **Некоректна валідація тексту вправ**
**Файл:** `handlers/workout_handlers.py` (рядок 132)
**Проблема:** `message.text.strip().split()` не обробляє випадки з комами, крапками
**Ризик:** LOW-MEDIUM - користувач може ввести "50,5 10" або "50. 10"
**Рішення:** Використати regex для парсингу

```python
import re
match = re.match(r'(\d+(?:\.\d+)?)\s+(\d+)', message.text.strip())
if not match:
    await message.answer("❌ Неправильний формат...")
    return
weight, reps = float(match.group(1)), int(match.group(2))
```

### 7. **Відсутність обмеження на розмір JSON**
**Файл:** `models/program.py` (рядок 16)
**Проблема:** `program_data: Mapped[dict] = mapped_column(JSON)` без обмеження розміру
**Ризик:** MEDIUM - великі програми можуть перевантажити БД
**Рішення:** Додати валідацію розміру програми або використати Text + JSON.loads/dumps

### 8. **Відсутність транзакції при створенні workout**
**Файл:** `handlers/workout_handlers.py` (рядок 63-69)
**Проблема:** Workout створюється, але якщо далі станеться помилка - workout залишиться порожнім
**Ризик:** LOW - orphan workout records
**Рішення:** Обгорнути в try/except або видаляти workout якщо не додано жодної вправи
